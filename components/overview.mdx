The `Component` interface is the foundation of every renderable element in Clique. It defines a minimal, consistent contract: produce a styled string, and know how to print it. Every built-in component — `Box`, `Divider`, `Frame`, `Tree`, `ItemList`, `Table`, and `ProgressBar` — implements this interface, so you can treat them all the same way at the call site.

## Interface Methods

### `get()`

Builds and returns the fully formatted string representation of the component without printing it. Useful when you want to compose output, store it, or pass it somewhere else.

```java
String rendered = Clique.divider(40).get();
```

<Note>
  Each call to `get()` performs a full render — no caching is guaranteed by the interface. Individual implementations may document their own caching behavior if applicable.
</Note>

### `render()`

Prints the component to `System.out`, followed by a newline. This is the most common way to display a component.

```java
Clique.box()
    .content("Hello, World!")
    .render();
```

### `render(PrintStream)`

Prints the component to a specific `PrintStream`. Use this to redirect output to `System.err`, a file stream, or any other custom stream.

```java
Clique.box()
    .content("[red, bold]Something went wrong[/]")
    .render(System.err);
```

<Warning>
  Passing `null` as the stream throws a `NullPointerException`.
</Warning>

## Using `Component` as a Type

Since every Clique component shares the `Component` interface, you can store and pass them generically without committing to a concrete type:

```java
Component warning = Clique.box()
    .dimensions(50, 5)
    .content("[yellow]Proceed with caution[/]");

warning.render();
```

This also makes it easy to build collections of components and render them together in a loop:

```java
List<Component> report = List.of(
    Clique.divider(60, "blue").title("Summary"),
    Clique.table(TableType.BOX_DRAW).headers("Key", "Value").row("Status", "OK"),
    Clique.divider(60, "blue")
);

report.forEach(Component::render);
```

## Implementing `Component`

`Component` is a functional interface — only `get()` is abstract. The `render()` and `render(PrintStream)` methods are provided as defaults, so you only need to implement `get()` to create a fully working component.

A common pattern is a live clock that re-evaluates on every render:

```java
Component clock = () -> {
    var now = java.time.LocalTime.now();
    return "[cyan]%02d:%02d:%02d[/]".formatted(now.getHour(), now.getMinute(), now.getSecond());
};

clock.render(); // prints current time to stdout
```

Custom components can also be nested inside a `Frame`, since `Frame.nest()` accepts any `Component`. The clock will be re-evaluated on every call to `frame.render()`:

```java
Clique.frame()
    .nest(clock)
    .render();
```

## Things to Watch Out For

- `get()` never returns `null`.
- `render()` always appends a newline after the output.
- `render(null)` throws a `NullPointerException`.
- Each call to `get()` or `render()` is a full re-render. If your component does expensive work, handle caching yourself.
