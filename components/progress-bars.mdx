Progress bars provide inline visual feedback for long-running operations. Clique includes five built-in style presets, a flexible format string with token placeholders, dynamic per-range styling, smooth easing animations, and a one-liner iterable wrapper for collection processing.

## Quick Start

```java
ProgressBar bar = Clique.progressBar(100);

while (!bar.isDone()) {
    bar.tick();
    Thread.sleep(50);
}
```

`tick()` advances the bar by one step and re-renders it in place. When the bar reaches its total, `isDone()` returns `true` and a newline is printed to move the cursor past the completed bar.

## Predefined Presets

Pass a `ProgressBarPreset` as the second argument to `Clique.progressBar()` to use a built-in style:

### BLOCKS (Default)
```
████████████████████████████████░░░░░  80% [00:12/00:03]
```
- Complete: `█` &nbsp; Incomplete: `░`
- Length: 40
- Format: `:bar :percent% [:elapsed/:remaining]`

### LINES
```
▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▁▁▁▁▁▁▁▁▁▁ 80%
```
- Complete: `▂` &nbsp; Incomplete: `▁`
- Length: 50
- Format: `:bar :percent%`

### BOLD
```
▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▱▱▱▱▱▱▱▱ 80% | 80/100
```
- Complete: `▰` &nbsp; Incomplete: `▱`
- Length: 40
- Format: `:bar :percent% | :progress/:total`

### CLASSIC
```
[##############################====================] 60% [00:45]
```
- Complete: `#` &nbsp; Incomplete: `=`
- Length: 50
- Format: `[:bar] :percent% [:elapsed]`

### DOTS
```
●●●●●●●●●●●●●●●●●●●●●●●●●●●●●●○○○○○○○○○○○○○○○○○○○○○ 58%
```
- Complete: `●` &nbsp; Incomplete: `○`
- Length: 50
- Format: `:bar :percent%`

```java
ProgressBar bar = Clique.progressBar(100, ProgressBarPreset.DOTS);
```

## `fromPreset()`

Start from a preset and customize only what you need. All preset values are copied into the builder; anything you chain after overrides them:

```java
ProgressBarConfiguration config = ProgressBarConfiguration
    .fromPreset(ProgressBarPreset.BLOCKS)
    .format("[green]:bar[/] :percent% | :progress/:total")
    .length(60)
    .build();

ProgressBar bar = Clique.progressBar(100, config);
```

## Iterating Over a Collection

When processing a collection, wrap it with `Clique.progressBar(collection)` to skip the boilerplate. The total is inferred from the collection size and the bar ticks and renders automatically on each iteration:

```java
for (var file : Clique.progressBar(files)) {
    process(file);
}
```

Presets and custom configuration are supported too:

```java
// With a preset
for (var file : Clique.progressBar(files, ProgressBarPreset.DOTS)) {
    process(file);
}

// With custom configuration
ProgressBarConfiguration config = ProgressBarConfiguration.builder()
    .format("[blue]:bar[/] :progress/:total files [:elapsed/:remaining]")
    .build();

for (var file : Clique.progressBar(files, config)) {
    process(file);
}
```

<Warning>
  `IterableProgressBar` is **single-use**. Iterating over the same instance twice throws `IllegalStateException`.
</Warning>

## Progress Bar Configuration

Build a fully custom progress bar style using `ProgressBarConfiguration.builder()`.

### `length(int)`

Width of the bar visualization in characters:

```java
.length(50)
```

### `complete(char)` and `incomplete(char)`

Characters used for filled and unfilled portions:

```java
.complete('▓')
.incomplete('░')
```

### `ticksPerUnit(int)`

Maps multiple ticks to a single logical unit. Enables the `:units` and `:total-units` tokens. Useful when each item has multiple internal steps:

```java
.ticksPerUnit(5)
```

With `ticksPerUnit(5)` and a total of `50` ticks, `:total-units` renders as `10` and `:units` increments automatically as ticks accumulate.

### `format(String)`

Template string for the progress bar output. Supports the following tokens:

| Token | Description |
|---|---|
| `:bar` | The filled/unfilled bar visualization |
| `:percent` | Current percentage (0–100), right-aligned to 3 chars |
| `:progress` | Current tick count, right-aligned to total width |
| `:total` | Total tick count |
| `:elapsed` | Elapsed time in `MM:SS` |
| `:remaining` | Estimated remaining time in `MM:SS`; `--:--` if unavailable |
| `:units` | Completed units (`currentTick ÷ ticksPerUnit`) |
| `:total-units` | Total units (`total ÷ ticksPerUnit`) |

```java
.format("[cyan]:bar[/] :percent% | :progress/:total")
```

### `parser(MarkupParser)`

Use a custom parser for markup processing in the format string:

```java
.parser(Clique.parser())
```

## Dynamic Styling

Change the format string — and with it the colors — based on the current progress percentage.

### `styleRange(int from, int to, String format)`

Apply a format string when the percentage is within a given range:

```java
ProgressBarConfiguration config = ProgressBarConfiguration.builder()
    .styleRange(0,   30,  "[red]:bar[/] :percent% [red]Starting...[/]")
    .styleRange(30,  70,  "[yellow]:bar[/] :percent% [yellow]In Progress...[/]")
    .styleRange(70,  100, "[green]:bar[/] :percent% [green]Almost Done![/]")
    .build();

ProgressBar bar = Clique.progressBar(100, config);
```

### `styleWhen(Predicate<Integer>, String format)`

Use a predicate for custom conditions:

```java
ProgressBarConfiguration config = ProgressBarConfiguration.builder()
    .styleWhen(p -> p <= 50,           "[red]:bar[/] :percent%")
    .styleWhen(p -> p > 50 && p < 90, "[yellow]:bar[/] :percent%")
    .styleWhen(p -> p >= 90,           "[green]:bar[/] :percent%")
    .build();
```

## Easing Animations

Easing gives progress bars smooth, animated transitions between values instead of instant jumps. It's opt-in and runs on the calling thread.

You can attach an `EasingConfiguration` directly in the factory call as a shorthand:

```java
ProgressBar bar = Clique.progressBar(100, EasingConfiguration.DEFAULT);
```

### Constants

`EasingConfiguration.DEFAULT` gives you a ready-to-use animation with sensible values: `EASE_OUT_QUAD`, 500 ms duration, 20 frames, and a threshold of 5:

```java
ProgressBarConfiguration config = ProgressBarConfiguration.builder()
    .easing(EasingConfiguration.DEFAULT)
    .build();

ProgressBar bar = Clique.progressBar(100, config);
```

`EasingConfiguration.DISABLED` is an explicit no-op — pass it anywhere an `EasingConfiguration` is accepted to opt out of animation entirely:

```java
ProgressBarConfiguration config = ProgressBarConfiguration.builder()
    .easing(EasingConfiguration.DISABLED)
    .build();
```

### Custom Easing Configuration

```java
EasingConfiguration easing = EasingConfiguration.builder()
    .function(EasingFunction.EASE_OUT_CUBIC)
    .duration(500)   // total animation time in milliseconds
    .frames(30)      // steps in the animation; frame delay = duration / frames
    .threshold(10)   // ticks below this skip animation and jump instantly
    .build();

ProgressBarConfiguration config = ProgressBarConfiguration.builder()
    .easing(easing)
    .build();

ProgressBar bar = Clique.progressBar(100, config);
bar.tickAnimated(40); // smooth 500ms animation
bar.tickAnimated(3);  // below threshold — jumps instantly
```

### `tickAnimated(int)`

Advances the bar by the given amount, applying the configured easing if the amount meets the threshold. If easing is not configured, or the tick is below the threshold, it falls through to a regular `tick()`.

<Warning>
  `tickAnimated()` **blocks the calling thread** for the duration of the animation. For CLI tools where the bar is the main event, this is fine. If that's a problem, run it on a separate thread yourself.
</Warning>

Unlike `tick()`, `tickAnimated()` calls `render()` for every animation frame automatically — you don't need to call it afterward.

### Easing Functions

All functions follow the naming convention from [easings.net](https://easings.net). `EASE_IN` accelerates into the animation, `EASE_OUT` decelerates out of it, `EASE_IN_OUT` does both.

| Function | Feel |
|---|---|
| `LINEAR` | Constant speed, no curve |
| `EASE_IN_SINE` | Gentle acceleration |
| `EASE_OUT_SINE` | Gentle deceleration |
| `EASE_IN_OUT_SINE` | Soft on both ends |
| `EASE_IN_QUAD` | Moderate acceleration |
| `EASE_OUT_QUAD` | Moderate deceleration (default) |
| `EASE_IN_OUT_QUAD` | Balanced curve |
| `EASE_IN_CUBIC` | Strong acceleration |
| `EASE_OUT_CUBIC` | Strong deceleration |
| `EASE_IN_OUT_CUBIC` | Dramatic on both ends |

For progress bars, `EASE_OUT_QUAD` and `EASE_OUT_CUBIC` tend to feel the most natural — they move fast at first and settle into place.

### Mixing Animated and Instant Ticks

You can mix `tickAnimated()` and `tick()` freely. Animate the big jumps; tick instantly through the small ones:

```java
ProgressBar bar = Clique.progressBar(1000, config);

// Large batch arrives — animate it
bar.tickAnimated(150);

// Process items individually — instant, no overhead
for (int i = 0; i < 50; i++) {
    processItem();
    bar.tick();
}
bar.render();

// Another large batch
bar.tickAnimated(200);
```

## Quick Examples

### Downloading a File

```java
ProgressBarConfiguration config = ProgressBarConfiguration.builder()
    .length(50)
    .complete('▓')
    .incomplete('░')
    .format("[cyan]:bar[/] :percent% | :progress/:total MB")
    .build();

ProgressBar bar = Clique.progressBar(totalMB, config);

while (downloading) {
    int downloaded = getDownloadedMB();
    bar.tick(downloaded);
    Thread.sleep(100);
}
```

### Processing a File List

```java
for (var file : Clique.progressBar(files)) {
    process(file);
}
```

### Dynamic Styling

```java
ProgressBarConfiguration config = ProgressBarConfiguration
    .fromPreset(ProgressBarPreset.DOTS)
    .styleRange(0,   50,  "[red]:bar[/] :percent% [dim]Processing...[/]")
    .styleRange(50,  90,  "[yellow]:bar[/] :percent% [dim]Finalizing...[/]")
    .styleRange(90,  100, "[green]:bar[/] :percent% [bold]Complete![/]")
    .build();

for (var file : Clique.progressBar(files, config)) {
    process(file);
}
```

### Steps Per Unit

```java
// 10 files, 5 steps each = 50 ticks, displayed as units
ProgressBarConfiguration config = ProgressBarConfiguration.builder()
    .ticksPerUnit(5)
    .format(":bar :percent% | :units/:total-units files [:elapsed/:remaining]")
    .build();

ProgressBar bar = Clique.progressBar(50, config);

for (File file : files) {
    for (int step = 0; step < 5; step++) {
        process(file, step);
        bar.tick();
    }
}
```

## Things to Watch Out For

- A negative total throws `IllegalArgumentException`.
- Passing `null` for a configuration throws `NullPointerException`.
- `IterableProgressBar` is **single-use** — iterating twice throws `IllegalStateException`.
- `tickAnimated()` blocks the calling thread for the full animation duration.
